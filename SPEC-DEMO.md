# SPEC-DEMO — спецификация демонстрационной версии

PHASE 2, дата 2026-10-13. Статус: **Proposed, ждёт согласования заказчиком** (кроме решений A-24 и ранее утверждённых A-01…A-23 из [DECISIONS.md](DECISIONS.md)).

Это спецификация **демо для презентации**, а не production-сайта. Полная структура — [docs/INFORMATION-ARCHITECTURE.md](docs/INFORMATION-ARCHITECTURE.md) (далее IA), границы DEMO/POST-DEMO — IA §12. Здесь не повторяется то, что уже зафиксировано там: даются только состав демо, поведение элементов и критерии приёмки. Визуальные требования — [DESIGN-BRIEF.md](DESIGN-BRIEF.md), стек и структура — [ARCHITECTURE-DEMO.md](ARCHITECTURE-DEMO.md), порядок работ — [PLAN-DEMO.md](PLAN-DEMO.md).

Обозначения: **S** — текст источника, дословно ([docs/content/source/](docs/content/source/)); **U** — интерфейсная подпись (Proposed, A-03; список для согласования — Q-23); **M** — маркер незавершённого (`ADDRESS_PENDING`, `DESCRIPTION_PENDING`, пометки демо). Страницы называются по ID из IA (PG-xx).

## 1. Цель демо

Показать заказчику, как будет выглядеть и вести себя новый сайт, и получить его решения до начала полноценной разработки (A-17). Демо **не** выдаёт себя за готовый сайт и не заменяет `ses-dv.ru`.

## 3. Аудитория презентации

Первичная — руководство ООО «Связь Энергострой» и ответственные за сайт. Роли и число участников неизвестны (Q-28) и не предполагаются. Посетители реального сайта (заказчики-организации, кандидаты) демо не видят: оно в закрытом показе (IA §12.3).

## 7. Границы навигации

Три класса элементов, видимо различимых:

| Класс | Признак | Элементы |
|---|---|---|
| **Рабочий** | настоящая ссылка/кнопка, переход или действие | меню, логотип, `/services`, `/projects`, `/projects/tlt`, `/about`, `/contacts`, `/privacy`, `tel:`, `mailto:`, WhatsApp, якоря `/services#…`, «К каталогу», «Заказать звонок», «Заказать», «Сотрудничать», «Обсудить задачу» |
| **Демо-действие** | работает, но результат — демонстрация | отправка формы (§12) |
| **Недоступный** | не `<a>` и не `<button>`; нет hover/pointer/стрелки; текстовая пометка «В полной версии» или «Страница в полной версии» (не только цвет); не получает фокус | 13 карточек проектов, 12 видов работ ТЛТ, «Вакансии» в footer |

Правила: нет перехода на `404` из интерфейса; нет `href="#"`; нет редиректов на главную; нет ссылок на `ses-dv.ru` (в том числе на старые страницы); внешние только `tel:`, `mailto:`, `https://wa.me/…`. Исключения — тексты политики (§6.7), где адреса сайта — часть дословного текста и не являются ссылками.

## 9. Требования к desktop и mobile

| Параметр | Требование |
|---|---|
| Проверяемые ширины | 1440, 1280, 1024, 768, 390, 360; страница не ломается на 320 |
| Горизонтальная прокрутка | нет ни на одной ширине |
| Масштаб | текст читается при масштабе 200 % без потери содержимого |
| Цели нажатия | ≥ 44 × 44 px на touch |
| Mobile | нижняя панель из двух кнопок, меню-шторка; шапка компактная; первый экран главной содержит заголовок, строки hero и кнопки |
| Клавиатура | всё рабочее достигается и применяется клавишами; видимый фокус; диалог удерживает фокус |
| Контраст | текст ≥ 4,5 : 1, крупный и границы полей ≥ 3 : 1 (WCAG 2.2 AA) |
| Семантика | один `<h1>` на страницу; иерархия заголовков без пропусков; `lang="ru"`; у кнопок доступные имена |
| Ресурсы | без внешних запросов (шрифты, карты, скрипты — только свои); JS на странице ≤ 20 КБ gzip; ориентиры CLS < 0,1, LCP < 2,5 с в локальной проверке |
| Браузеры | актуальные Chrome и Edge (проверяются), Safari и Firefox — смоук-проверка, если есть доступ; иначе NOT_VERIFIED |
| Индексация | `<meta name="robots" content="noindex, nofollow">` на каждой странице; sitemap нет; `robots.txt` не закрывается через `Disallow` (краулер, которому обход запрещён, не прочитает `noindex`). Реальная защита — доступ и заголовок `X-Robots-Tag` на хостинге (DEMO-15, Q-28) |

## 10. Требования к исходным текстам

- Тексты S переносятся дословно из `docs/content/source/` (A-03): символы, регистр, кавычки «» и " как в источнике; типографика — только средствами CSS. Исправления опечаток — только после согласования (Q-24).
- Хранение: тексты S лежат в данных отдельно от подписей U ([ARCHITECTURE-DEMO.md](ARCHITECTURE-DEMO.md) §3); сборка сверяет S со снимками скриптом ([PLAN-DEMO.md](PLAN-DEMO.md) DEMO-03).
- Новые рекламные формулировки, цифры, даты, заказчики, статусы, цены не создаются. У «Проектирования» — только название.
- Видимые в демо дефекты источника (заказчику сообщить до показа): «приезжаейте» (контакты), «Перетарочных коплексов» (ТЛТ), повтор фрагмента в названии первого вида работ ТЛТ («ГНБ под автодорогой Д-1 … тепловодоснабжения и ГНБ под автодорогой Д-1 … напорной канализации»), «строительно — монтажных» (каталог), склейка раздела 6 в политике.
- Заголовок и описание страниц (`<title>`, meta) — интерфейсные (U); `ses-dv.ru`-метаописания источника («Прокол для водопровода» на контактах) не переносятся.
- Демо отмечено на **каждой** странице: полоса «Демонстрационная версия» в самом верху страницы (не закреплена, при прокрутке уходит) и пометка в footer (U/M); текст: «Демонстрационная версия. Не является действующим сайтом компании. Тексты перенесены с действующего сайта, их актуальность подтверждается заказчиком».

## 11. Требования к изображениям

- Фото нет и до получения от заказчика (A-06, Q-10): **только явные заглушки**. Ни стоковых кадров, ни файлов старого сайта (скачивание файлов требует отдельного разрешения; в демо не планируется).
- Заглушка — компонент с нейтральным фоном, сохраняющий итоговую пропорцию, и видимой подписью «Место для фотографии» (U), не имитирующей фото. На фоне hero — такая же заглушка.
- Слоты: hero 1; главная — 6 карточек проектов; `/projects` — 14; ТЛТ — галерея 6. Страницы «Услуги», «О компании», «Контакты» без фото.
- Замена: в данных поля `image` (путь, alt, пропорция). Пустое поле — заглушка; сборка не падает. Для фото alt задаёт заказчик/редактор; у заглушек alt пустой (декоративные) и текстовая подпись скрыта от скринридера как повтор.
- Логотип — текстовый знак-заглушка до вектора от заказчика (Q-07, Q-33).
- Если до показа появятся 2–3 фото (Q-32), заменяются только данные, дизайн не меняется.

## 12. Ограничения демонстрационных форм

Один компонент: диалог (везде), встроенный на `/contacts` и в H-05.

| Правило | Реализация |
|---|---|
| Нет сетевого запроса | `fetch`/XHR/beacon/WebSocket отсутствуют; проверка в e2e: ноль исходящих запросов при отправке |
| Нет хранения | нет `localStorage`, `sessionStorage`, cookie, IndexedDB; данные живут только в полях до закрытия диалога или отправки |
| Нет данных в URL | у полей нет `name`, у формы нет `action`: при сбое JS браузер не может сериализовать данные в адрес; без JS видна подпись «для работы демонстрационной формы нужен JavaScript» (U) и ссылка на контакты |
| Честность до отправки | в форме на виду, до любого действия: «Демонстрационная форма. Заявка не будет отправлена» (U) |
| Честность после отправки | сообщение (U): «Это демонстрация. Заявка не отправлена, введённые данные не сохранены»; **не используются** «Благодарим за обращение…» и «Ваш заказ принят!» (Q-23) |
| Поля | подписи S из `_shared.md`: «Ваш Email», «Ваше имя» (обяз.), «Ваш телефон» (обяз.), «Ваш вопрос»; подсказки S: «Email», «Имя», «Введите Ваш вопрос». Подсказка телефона — U «+7 (000) 000-00-00» вместо «+1(000)000-0000» источника (Q-24). Контекст (услуга/проект) — U, показан и не редактируется |
| Проверка | клиентская: пустые обязательные поля, формат e-mail при заполнении; текст ошибок (U) связан с полем; фокус на первую ошибку |
| Согласие | дословно «Нажимая кнопку "Отправить" вы соглашаетесь с Политикой конфиденциальности» (S), ссылка на `/privacy`. Отдельный флажок согласия и юридические формулировки — POST-DEMO (Q-31) |
| Кнопка | «Отправить» (S) |
| После отправки | поля очищаются, показано сообщение, кнопки «Закрыть» (диалог) / «Заполнить снова» (U) |
| Доставка, антиспам, капча | не реализуются, не имитируются (Q-05) |

# ARCHITECTURE-DEMO — техническое решение для демо

PHASE 2, дата 2026-10-13. Статус: **Proposed** (уточняет P-01, P-02, P-04; фиксируется как P-19). Зависимости не установлены, frontend не создан.

## 1. Решение

**Astro + TypeScript + Tailwind CSS, статическая сборка, без React, без CMS, backend и базы данных.** Контент — типизированные TS-модули и один Markdown-файл (политика). Интерактив — три небольших скрипта на ванильном TypeScript.

## 2. Сравнение

Оценка по фактам проекта: что нужно демо — 8 статических страниц, три интерактивных поведения (меню, диалог, демо-форма), контент в репозитории, без аналитики и серверной части ([SPEC-DEMO.md](SPEC-DEMO.md)). Пометки: **V** — проверено в этой сессии; **K** — общеизвестное свойство инструмента, в проекте не измерялось.

| Критерий | A. Astro | B. Next.js (`output: 'export'`) | Вывод |
|---|---|---|---|
| Скорость разработки демо | `.astro` — шаблоны HTML + TS; три скрипта; нет гидратации (K) | Те же страницы на React; меню, диалог, форма — `use client` компоненты (K) | A чуть быстрее; разница небольшая |
| Скорость загрузки | страница без JS по умолчанию, JS только у трёх модулей (K) | в сборку входит среда выполнения React даже для статики (K); не измерялось | A; замер baseline в DEMO-02, ориентир ≤ 20 КБ gz JS |
| SEO | статический HTML; метаданные в шаблоне; sitemap — интеграция (K) | статический HTML; Metadata API (K) | равны; демо закрыто от индексации (`noindex`) |
| Работа с контентом | типизированные TS-данные, `.md` импортируется как компонент; нет схемы и CMS (K) | TS-данные так же; для Markdown нужен MDX-плагин или свой разбор (K) | A проще |
| Деплой | `dist/` — набор файлов для любого статического хостинга, в том числе российского (P-04) (K) | экспорт — тоже файлы, но с ограничениями: нет оптимизации `next/image` без своего загрузчика, нет middleware/ISR (K) | A проще |
| Последующее расширение | добавление проекта/услуги — запись данных; форма — endpoint с адаптером Node или отдельный сервис в РФ (P-03); React-острова добавляются точечно (K) | богаче экосистема приложений; форма — API-маршрут, требует режима Node, то есть отказа от чистого экспорта (K) | A достаточен: личный кабинет и т. п. не планируются (A-10) |
| Скиллы проекта | `ui-ux-pro-max` содержит `data/stacks/astro.csv` и `nextjs.csv` (V); `better-typography` сопоставляет CSS с утилитами Tailwind (V); упоминаний Astro/Next в `SKILL.md` остальных скиллов нет (V: поиск), другие файлы скиллов не читались | то же | не различает; Tailwind поддержан |
| Стоимость поддержки | деревья зависимостей: `astro`, `tailwindcss`, `@tailwindcss/vite` (K); версии на 2026-10-13: Astro 7.3.8, Tailwind 4.3.3 (V: `npm view`) | `next`, `react`, `react-dom`, `tailwindcss`; Next 16.4.0 (V) | A меньше; мажорные версии выходят быстро у обоих |
| Риск миграции демо → production | остаётся Astro; данные и компоненты — разметка | остаётся Next | оба низкие; данные не привязаны к фреймворку |
| Окружение | Node `v24.19.0` (V) подходит: Astro требует `>=22.12.0`, Next `>=20.9.0` (V: `npm view … engines`); Windows 11, локальная сборка | то же | не различает |

**Почему A, а не «популярный» B.** Демо — набор статических страниц; JS нужен лишь в трёх точках. Next добавляет среду React и ограничения экспорта без выгоды для этих задач. Если позже появятся требования к приложению (аутентификация, динамика), добавляются острова React или серверный слой — переписывать данные и вёрстку не придётся.

**Что заставит пересмотреть:** обязательное требование заказчика/подрядчика поддерживать сайт на React/Next; необходимость серверных страниц в первой версии production; невозможность подтвердить совместимость Astro 7 с выбранным TypeScript (§5).

## 3. Структура проекта (предварительная)

```text
src/
  pages/            index, services, projects/index, projects/[slug], about, contacts, privacy, 404
  layouts/          BaseLayout.astro            шапка, подвал, диалог, полоса «Демонстрационная версия», noindex
  components/
    layout/         Header, MobileMenu, BottomBar, Footer, DemoBanner
    ui/             Button, PhotoSlot, Gallery, Badge, SectionHeading, Breadcrumbs, InertNote
    sections/       Hero, ServiceList, ProjectGrid, AdvantageList, CtaBlock
    forms/          DemoRequestForm, RequestDialog
  data/
    source/         services, projects, advantages, company, contacts, tlt   ← тексты S, дословно
    ui.ts                                                                   ← подписи U, единый файл на согласование
    site.ts, nav.ts                                                         ← маркеры M, маршруты
  content/          privacy.md                                              ← S, из docs/content/source/privacy.md
  scripts/          menu.ts, dialog.ts, demo-form.ts                         ← клиентский код
  styles/           tokens.css (токены, @theme), global.css (базовые стили, импортирует tokens.css)
  assets/placeholders/                                                      ← заглушки фото (SVG)
public/             favicon
scripts/            check-tokens.mjs (DEMO-02), check-copy.mjs (DEMO-03), check-links.mjs (DEMO-04)  ← проверки (Node, не часть сайта)
tests/e2e/          *.spec.ts
```

Разделение: **страницы** собирают секции и берут данные; **секции** — крупные блоки страниц; **компоненты `ui/`** не знают о данных; **данные** лежат отдельно от вёрстки и разделены на S (проверяются на дословность) и U (интерфейс). Любой текст в шаблонах — только из `data/`.

Типы данных (набросок, уточняется в DEMO-03; слаги проектов и якоря услуг `s-01`…`s-10`):

```ts
type Photo = { src?: string; alt?: string; ratio: '2:1' | '16:10' | '4:3' };   // нет src → заглушка
type Service = { id: 's-01'; slug: string; title: string; descriptionPending?: true };
type Project = { id: 'prj-14'; slug: string; title: string; hasPage: boolean; photo: Photo };
```

`hasPage` управляет тем, станет ли карточка проекта ссылкой: появление новой страницы — правка данных и добавление записи, а не вёрстки. Маршрут `projects/[slug]` строится только для проектов с `hasPage`.

## 4. Принципы

- **Минимум зависимостей.** Нет UI-библиотек, иконочных шрифтов, библиотек анимации, React, Alpine и т. п. Иконки — встроенный SVG.
- **Статика без запросов.** Нет внешних ресурсов; шрифты — локальные WOFF2; нет аналитики и сторонних сервисов (CLAUDE.md).
- **Клиентский код.** Диалог и меню-шторка — нативный `<dialog>` с `showModal()` (ловушка фокуса, Esc и инертность фона обеспечивает браузер); демо-форма — клиентская проверка и локальное состояние, без `fetch` и хранения. Всё ≤ 20 КБ gz.
- **Прогрессивное улучшение.** Без JS работают навигация, `tel:`, `mailto:`, ссылки на `/contacts#request`; форма в этом случае не отправляется (SPEC-DEMO §12).
- **Токены.** Цвета, размеры и радиусы — CSS-переменные в `@theme` (Tailwind 4), задаются в PHASE 4; в компонентах нет «сырых» HEX ([BRAND-COLORS.md](docs/BRAND-COLORS.md) §7).
- **Заглушки.** `PhotoSlot` принимает `Photo`; без `src` рисует заглушку с подписью. Замена фото — правка данных.
- **Демо-режим.** Переменная `PUBLIC_DEMO=true` по умолчанию включает `<meta name="robots" content="noindex, nofollow">` и полосу «Демонстрационная версия» (`robots.txt` не закрывается через `Disallow`: краулер не прочитает `noindex`; заголовок `X-Robots-Tag` — на хостинге, DEMO-15); в production-сборке полоса выключается, а `noindex` снимается отдельным решением (B-09, B-11).

## 5. Зависимости и проверки

Устанавливаются в DEMO-02 после гейта G2 (PLAN-DEMO); версии фиксируются `package-lock.json`, перед установкой проверяются `npm view`.

| Пакет | Для чего | Обязателен |
|---|---|---|
| `astro`, `tailwindcss`, `@tailwindcss/vite` | сборка, стили | да |
| `typescript`, `@astrojs/check` | проверка типов (`astro check`) | да |
| `eslint`, `eslint-plugin-astro`, `typescript-eslint` | lint + правила доступности для `.astro` | да |
| `prettier`, `prettier-plugin-astro` | единый формат | да |
| `@playwright/test` (+ загрузка браузера) | e2e: переходы, отсутствие запросов, фокус, скриншоты | да; браузеры — отдельное разрешение на загрузку (≈ сотни МБ) |
| `@axe-core/playwright` | автоматическая проверка доступности | опционально |
| шрифт (`@fontsource…` или локальные файлы) | выбор в PHASE 4 | да |

Риск версий: Astro 7 и TypeScript 7 — свежие мажорные версии на 2026-10-13 (V). В DEMO-02 проверяется, что `astro check` и `typescript-eslint` работают; если нет — предыдущая мажорная версия TypeScript без смены стека, при неудаче — Next.js (P-19).

Скрипты (`package.json`, предложение): `dev`, `build`, `preview`, `check` (`astro check`), `lint`, `format:check`, `test` (Playwright), `verify` = `check` + `lint` + `format:check` + `build` + `check-copy` + `check-links` (к моменту создания скриптов; PLAN-DEMO §0).

## 6. Что сознательно не добавляется

Backend, CMS, БД, админка, аналитика, формы-сервисы, i18n, MDX, content collections, sitemap, RSS, React-интеграция, UI-кит. Каждое подключается отдельным решением после демо (см. [SPEC-DEMO.md](SPEC-DEMO.md) §13).

## 7. Путь от демо к production

| Что | Как |
|---|---|
| Новые страницы | запись данных + шаблон `[slug]`; шаблоны T-01…T-09 уже существуют |
| Форма | компонент остаётся; добавляется обработчик на сервере в РФ (P-03) и настоящее согласие; демо-пометки снимаются |
| Метрика | подключение в `BaseLayout` после решения (A-09, Q-14) |
| SEO-миграция | sitemap, canonical, 301/410 на хостинге по [URL-MIGRATION.md](docs/URL-MIGRATION.md); возможность 410 зависит от хостинга (не проверено) |
| Хостинг и защита предпросмотра | Q-28, Q-04; статический `dist/` не привязан к провайдеру |
| Окружение | рабочая ветка, Windows; перенос строк фиксируется `.gitattributes` в DEMO-02 |

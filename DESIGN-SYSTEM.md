# DESIGN-SYSTEM — минимальная дизайн-система демо «Связь Энергострой»

PHASE 4, 2026-10-13. Статус: **Proposed** (на согласовании заказчика), кроме отмеченного Approved: палитра (A-12), шрифтовая пара (A-26), логотип как источник (A-27), визуальная основа (A-25).

Это не новый дизайн, а фиксация решений прототипа главной [`design/explorations/ses-home-v1/`](design/explorations/ses-home-v1/index.html) (референс EverMod) в виде токенов и компонентов, достаточных для шести страниц демо. Реализует Sonnet на PHASE 5 (Astro + TypeScript + Tailwind): здесь описано **что** и **с какими значениями**, не **как** верстать в конкретном фреймворке.

**Визуальный style guide:** [`design/system-preview/index.html`](design/system-preview/index.html) (открывается двойным щелчком; значения цвета, размеров и контраста читает из токенов, поэтому не расходится с системой). Скриншоты — [`design/system-preview/screenshots/`](design/system-preview/screenshots/).

## 1. Принципы визуального языка

1. **Минимализм.** Светлая нейтральная база, белые карточки без рамок, один тёмный экран (hero) и тёмный подвал. Декора нет: никаких теней кроме двух (плашка проекта, плавающая карточка), градиентов в интерфейсе и иллюстраций.
2. **Типографика несёт композицию.** Крупные заголовки Manrope с отрицательным трекингом; акцентное слово — салатовым только на тёмном.
3. **Один фирменный акцент.** Зелёный `--color-brand` — действие и ссылки; салатовый `--color-accent` — главная кнопка и метки. Салатовый на светлом никогда не несёт текст и смысл.
4. **Модульная сетка.** Один контейнер 1200 px, равные промежутки, карточки одной высоты в ряду.
5. **Честность демо.** Недействующее выглядит недействующим: у недоступных элементов нет hover, они не ссылки и подписаны словами; у заглушек фото явная пометка; форма объявляет, что ничего не отправляет.
6. **Умеренные радиусы по роли:** чем крупнее поверхность, тем больше радиус; вложенный элемент имеет радиус меньше контейнера.
7. **Не добавлять.** Новые декоративные элементы, цвета, тени, начертания и анимации — только через решение владельца.

### 2.3 Правила использования

- **Где.** Header над hero — `logo-wordmark-on-dark.svg`; header после прокрутки и на внутренних страницах — `logo-wordmark.svg`; footer — `logo-full-on-dark.svg`; вкладка браузера — `favicon.svg`.
- **Почему в шапке только название.** Полный знак при высоте шапки 72–84 px имеет высоту названия около 10 px — нечитаемо. Горизонтальная композиция (знак + название) требует перекомпоновки оригинала и не создавалась (Q-34).
- **Размеры в интерфейсе.** Шапка: ширина 200 px (≥ 641 px) и 168 px (≤ 640); подвал: 208 px. Высота — автоматически по пропорции (`height: auto`, у `<img>` заданы `width`/`height`).
- **Минимумы.** Полный знак — 160 px по ширине; название — 160 px; знак — 24 px (favicon — 16 px).
- **Охранное поле** — высота заглавной «С» в названии = 7,7 % ширины полного знака. В него не заходят другие элементы.
- **Фон.** Светлый вариант — на `--color-surface` и `--color-bg`; тёмный — на `--color-bg-dark`, hero с затемнением. На фотографию — только под затемнением. Салатовые части знака на светлом слабо контрастируют (1,7 : 1 и 2,6 : 1): знак на светлом сопровождается названием.
- **Нельзя:** перерисовывать, растягивать непропорционально, менять шрифт, перекрашивать (кроме белого названия на тёмном), добавлять тень, обводку, градиент; использовать растровый логотип со старого сайта.
- **Доступность.** Ссылка-логотип несёт `aria-label="Связь Энергострой — на начало страницы"`, картинки внутри — `alt=""`. Для логотипа требования контраста WCAG не применяются; название на светлом 3,8 : 1, на тёмном (оригинальный цвет) 4,6 : 1, белое — 17,7 : 1.

### 2.4 Что требует согласования

Q-34 (горизонтальная версия), Q-35 (favicon), Q-36 (расхождение HEX), Q-37 (белое название на тёмном как официальное производное). Подробности — `DECISIONS.md`.

## 4. Типографика

Manrope — заголовки, кнопки, навигация, подписи; Golos Text — основной текст и интерфейс. Локальные WOFF2 (кириллица + латиница), `font-display: swap`. Лицензии OFL-1.1 лежат в `design/system/fonts/`. Используемые начертания присутствуют в переменных шрифтах: Manrope 200–800 (используются 400, 500, 600, 700), Golos Text 400–900 (используются 400, 500, 600). Все символы текста прототипа покрыты шрифтами (проверено по `unicode-range`: «, », „ “, —, №, ›, ·, ×, цифры, кириллица).

## 6. Отступы

Шаг 4 px: `--space-1…16` = 4, 8, 12, 16, 20, 24, 32, 40, 48, 56, 64. Вертикальный ритм: между секциями `--section-gap` = `clamp(56px, 6vw, 88px)`; заголовок секции → содержимое `--head-gap` = `clamp(24px, 3vw, 40px)`; внутри карточки 24 px (услуга), 28 px (плитка), 18 × 20 px (плашка проекта); блок обращения `clamp(24px, 3.4vw, 48px)`. Нечётные значения в компонентах (6, 10, 14, 18, 28, 36, 44) — оптическая подгонка, в новом коде использовать шкалу.

| `--shadow-raised` / `--shadow-float` | см. токены | Плашка проекта / плавающая карточка — единственные тени |

Пропорции изображений: hero 21 : 9; карточка проекта 16 : 10 (`.slot`); широкая 21 : 9 (`.slot--wide`); галерея 4 : 3 (`.slot--4x3`); mobile-кадр hero ≈ 4 : 5. Всегда `object-fit: cover`.
Ширины текста: H1 hero 11ch; строки hero 540 px; заголовок страницы 22ch; вводный абзац 60ch; подзаголовок обращения 34ch; `.prose` 68ch.

### 8.5 Карточка проекта — `.project`
`li.project` > `.slot` (заглушка или фото) + `.project__plate` (название `h3.project__title` + действие).
- **Активная:** справа `button.dot.dot--lime.dot--lg` с `aria-label="Открыть проект «…»"`.
- **Недоступная:** `.project--static`, вместо кнопки `p.project__off` «Страница в полной версии». Не ссылка, не получает фокус, нет hover. **Фальшивые ссылки запрещены.**
- Слот: `aspect-ratio: 16/10` (модификаторы `.slot--wide` 21:9, `.slot--4x3` 4:3), сетка и рамка-видоискатель, чип «Место для фотографии · 16 : 10». Нижние 64 px слота перекрывает плашка — главный объект фото в верхних 60 %. Фото: `<img class="slot__img" alt="…">` внутрь слота (абсолютное заполнение, `cover`), заглушка и чип скрываются сами. Сетка проектов 3 → 2 (≤ 960) → 1 (≤ 640).

### 8.6 Поля формы
- `.field` > `label` (всегда видимый, над полем) + `input`/`textarea` + `p.field__err[hidden]` (id `<id поля>-err`). Поле: высота 52 px, рамка 1,5 px `--color-border-strong`, радиус 12 px, текст 16 px.
- Состояния: hover — рамка text; focus-visible — контур 3 px brand + рамка brand; ошибка — `aria-invalid="true"`, рамка error, текст ошибки под полем (связан `aria-describedby`); заполнено — без изменений; disabled — disabled-bg.
- Валидация клиентская при отправке: пустые обязательные поля, телефон ≥ 10 цифр, формат e-mail; фокус на первое ошибочное поле. Флажка согласия в демо нет (Q-31): строка `.form__consent` дословно из источника.
- **Демо-пометка** `.demo-note` («Демонстрационная форма. Заявка не будет отправлена») стоит до любого действия; блочный вариант `.demo-note--block` — «место под материал» (например, документы на «О компании»). **Результат** `.form__result[role=status][aria-live=polite]` — пустой регион всегда в DOM; текст «Это демонстрация. Заявка не отправлена, введённые данные не сохранены» вставляется при отправке. Слов «Спасибо» и «Заявка принята» нет.
- Ограничения демо-формы (SPEC-DEMO §12): у формы нет `action`, у полей нет `name`, нет `fetch`/XHR, нет `localStorage`/cookie; `autocomplete="off"`, `spellcheck="false"` у телефона и e-mail.
- **Диалог:** нативный `<dialog class="modal">` + `showModal()`; Esc, крестик (44 px) и клик по фону закрывают, фокус возвращается на источник; при закрытии введённое сбрасывается; на ≤ 640 px — нижняя шторка. Контекст («Услуга: …», «Проект: …») показывается в `.modal__context`.

## 9. Интерактивные состояния

- **Hover** есть только у рабочих элементов. У недоступных (`.project--static`, `.row-list`, «Вакансии») его нет.
- **Focus-visible:** контур 3 px, смещение 3 px; цвет `--color-focus` на светлом, `--color-focus-on-dark` в `.on-dark` и над hero. Поле: смещение 2 px. `outline: none` не используется нигде, кроме `main` (программный фокус).
- **Active:** кнопки без сдвига, тёмнее/светлее по таблице §8.3.
- **Disabled:** нативный `disabled` (или `aria-disabled="true"`); цвета disabled-токенов, `cursor: not-allowed`.
- **Текущая страница:** `aria-current="page"`.
- Служебные классы `.is-hover`, `.is-focus`, `.is-active` существуют только для style guide.

## 10. Доступность

Принятые нормы: контраст AA (текст 4,5 : 1, крупный и нетекстовые элементы 3 : 1), цель касания ≥ 44 px (минимум WCAG 2.2 AA — 24 px), видимый фокус, клавиатурное управление, `prefers-reduced-motion`, reflow на 320 px.

- Семантика: `lang="ru"`, один `<h1>`, иерархия `h1 > h2 > h3`, `<main>`, `<nav aria-label>`, skip-link.
- Диалоги: нативный `<dialog>` — фокус удерживается, Esc, возврат фокуса.
- Иконки: декоративные — `aria-hidden`, функциональные — `aria-label`.
- Формы: видимые подписи, `aria-invalid`, `aria-describedby`, фокус на первую ошибку, пустой live-регион для результата.
- Масштаб: `viewport` без `maximum-scale`/`user-scalable`; 320 px без горизонтальной прокрутки.
- Известные отступления: бургер — `<a href="#footer-nav">` (в SPEC-DEMO §8: без JS это якорь на навигацию в подвале), хотя с JS он ведёт себя как кнопка; `autocomplete="off"` и отсутствие `name` у полей — требование SPEC-DEMO §12 (демо ничего не сохраняет и не передаёт).
- **Не заявляется** полное соответствие WCAG: проверены перечисленные в `PROGRESS.md` пункты; скринридеры, Safari и Firefox не проверялись.

## 11. Motion

Токены: `--motion-fast` .15 s, `--motion-base` .2 s. Допустимо: смена фона, цвета, рамки, подчёркивания; сдвиг карточки/кнопки на 1–3 px (`transform`); появление диалога (`opacity` + сдвиг 8 px, .2 s). Не допускается: параллакс, автоплей, бесконечные анимации, анимация размеров/позиции макета. `transition: all` не используется. `prefers-reduced-motion: reduce` отключает все переходы и анимации и плавную прокрутку глобально (проверено).

## 12. Работа с изображениями

- **До получения фото — только явные заглушки** «Место для фотографии» с пропорцией в чипе. Сток не выдаётся за проекты СЭС (CLAUDE.md). Ссылки на изображения старого сайта не используются.
- Фото вставляется как `<img>` с `width`/`height` и `object-fit: cover`; `alt` задаёт заказчик (декоративное — `alt=""`); ниже сгиба — `loading="lazy"`.
- Рекомендованные форматы: WebP (+ JPG), sRGB; hero ≤ 300 КБ, карточка проекта ≤ 150 КБ.

### Hero — только спецификация
Фотография **не добавлена**. Структура существующего hero: тёмный блок под прозрачной шапкой (`margin-top: −header`), высота `clamp(640px, 49vw, 740px)` (≈ 2 : 1 на 1440), слева текстовая колонка (вводная строка, H1 Display, три строки, три действия), справа условная рамка-видоискатель и плавающая карточка «Место для фотографии» (до 1180 px — у правого края, ≤ 820 px скрыты).

| Параметр | Требование |
|---|---|
| Размещение | Фон на всю ширину окна, `object-fit: cover`, точка фокуса задаётся `object-position` (по умолчанию справа по центру) |
| Пропорция и размер | 21 : 9; 2880 × 1235 px (минимум 1920 × 823 px) |
| Формат | WebP + JPG, sRGB, ≤ 300 КБ; без текста, логотипов и водяных знаков внутри кадра |
| Композиция | Объект — правая половина (от 52 %); левая половина спокойная, малодетальная; важное — в центральных 80 % высоты |
| Затемнение A (по умолчанию) | `linear-gradient(90deg, rgba(10,16,11,.72) 0%, .38 48%, 0 75%)` — допустимо, если в левых 50 % кадра нет пикселей ярче ≈ 72 % (≈ `#B9B9B9`): при α .38 это граница 4,5 : 1 для белого текста 18 px |
| Затемнение B (светлое фото) | `.72 → .56 на 48 % → .2`; при α ≥ 0,56 любой пиксель под текстом даёт белому тексту ≥ 4,5 : 1 |
| Затемнение C (mobile ≤ 820 px) | `linear-gradient(0deg, rgba(10,16,11,.82) 0%, .55 45%, .15 100%)`, текст внизу |
| Mobile | Кадр кадрируется до ≈ 4 : 5 по объекту; плавающая карточка и рамка скрыты; высота 560 px (≤ 820) / первый экран (≤ 640) |
| Проверка | Белый текст ≥ 4,5 : 1 на самом светлом пикселе зоны текста после затемнения (для крупного H1 достаточно 3 : 1) |
| Доступность | Фото декоративно (`alt=""`), текст hero всегда живой |

## 13. Адаптивность

Порядок: mobile (≤ 640) → планшет (≤ 960) → десктоп; компоновка меняется по §5. Названия переносятся, не обрезаются; flex- и grid-потомки с текстом имеют `min-width: 0`; карточки в ряду одной высоты; изображения не растягивают контейнеры. Цели касания ≥ 44 px, нижняя панель не перекрывает последний контент, диалог на mobile — нижняя шторка с `max-height: 92dvh`. Текст при 200 % масштабе и 320 px не теряет содержимого.

## 14. Правила для будущих страниц

1. Не вводить цвета, размеры текста, радиусы, тени и отступы вне токенов. Нужен новый — предложить через `DECISIONS.md`.
2. Использовать токены и классы: в Tailwind — перенести токены 1 : 1 в тему (`colors.brand`, `colors.accent`, `fontSize` из `--type-*`, `borderRadius` из `--radius-*`, `spacing` из шкалы), брейкпоинты `max-sm` ≈ 640, `max-md` ≈ 960 (используйте `max-*`-варианты, чтобы логика совпала с прототипом).
3. Страница = шапка (`data-header="solid"` без hero) → `.page-head` (крошки, один H1, лид) → секции с `--section-gap` → CTA-блок → footer. Hero с фото — только на главной.
4. Услуги и проекты — только готовые карточки; названия дословно; нет описания — «Описание будет добавлено». Недоступное не делать ссылкой.
5. Любое действие «Заказать/Сотрудничать/Обсудить» — диалог с контекстом (`data-open-request`, `data-context`, `data-subject`); на `/contacts` — прокрутка к встроенной форме.
6. Тексты старого сайта дословно; интерфейсные подписи — из списка (U) SPEC-DEMO; не придумывать описания, цифры, контакты, адрес (`ADDRESS_PENDING`).
7. Фото — только заглушки до получения от заказчика; слот не зависит от фото (макет не меняется при замене).
8. Один `<h1>`; новые интерактивные элементы — нативные (`button`, `a`, `dialog`); для иконок `aria-label`; после изменений прогнать проверки §«Проверки» в `PROGRESS.md`.
9. Не добавлять аналитику, внешние шрифты, CDN, скрипты третьих сторон, cookie, хранилища.
10. Нужны улучшения системы (флажок согласия, loading, фильтры) — после демо, отдельным решением.

## 15. Известные отступления прототипа от системы

Сохранены ради неизменности главной; при реализации на Astro не копировать: локальные стили текста (§4), размеры 17 px у `.cta__sub` и `3vw` у `.all-tile__title`, нечётные отступы (§6), литералы `rgba(...)` в заглушках слотов и hero-затемнении, пять локальных брейкпоинтов. Токены `--color-accent-mid`/`-deep` в UI используются только для состояния «active» (mid); deep пока не используется.

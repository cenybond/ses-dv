# Архитектура сайта

Существующий Astro 7 + TypeScript 6 + Tailwind 4 проект сохранён. HTML предварительно собирается в `dist/`. React, SPA-router, CMS и серверный рендеринг всего сайта не добавлены. Локальные WOFF2, SVG-логотип и токены остаются в `design/system/`. Исходная презентация Hero V4 `design/client-preview/hero/` сохранена отдельно.

## Ответственность каталогов

| Каталог | Содержание |
|---|---|
| `docs/content/source/` | Неизменяемые снимки фактического контента |
| `src/data/source/` | Типизированные тексты `{text, src}`, изображения и связи |
| `src/data/ui.ts`, `nav.ts` | Интерфейсные подписи, маршруты и навигация |
| `src/data/redirects.ts` | Реестр судьбы 50 старых URL |
| `src/data/site-config.ts` | Режим сборки и юридические release gates |
| `src/layouts/`, `components/` | Общая оболочка, блоки страниц и интерактивный UI |
| `src/pages/` | Статические страницы и генерируемые маршруты |
| `src/scripts/`, `styles/` | Browser TypeScript и стили |
| `design/system/` | Единственный источник токенов, шрифтов и логотипа |
| `server/` | Отдельный endpoint заявок, выключенный по умолчанию |
| `scripts/` | Сборочные проверки, тесты и локальный staging |

## Страницы и данные

Главная, каталог 10 услуг, каталог 14 проектов и их страницы, 12 видов работ ТЛТ, «О компании», «Вакансии», «Контакты», 404. Юридические `/privacy`, `/consent`, `/cookies` доступны для проверки как явно обозначенные черновики с noindex. Новости и документы скрыты до появления утверждённых материалов; PRJ-15 не публикуется. Полнота и причины исключений — [content-register](content-register.md).

Проекты генерируются `src/pages/projects/[slug].astro`, ТЛТ имеет отдельную страницу, виды работ — `src/pages/projects/tlt/[slug].astro`. Каждый маршрут использует BaseLayout; содержательные шаблоны различаются. `check-copy` сверяет фактические строки с источниками. Исходные формулировки не редактируются при переносе; редакторские предложения требуют отдельного согласования. Фотографии представлены подписанными слотами. Временная иллюстрация Hero не выдаётся за объект СЭС.

## Browser UI

BaseLayout подключает SEO-head, skip-link, Header, main, Footer, мобильное меню, нижнюю панель, RequestDialog и cookie UI. `site.ts` и `forms.ts` используют DOM-обработчики. Нативные dialog дают модальность/Escape, дополнительно реализован возврат фокуса. Без JavaScript основные ссылки, телефон/e-mail работают; кнопки заявки ведут на контакты, отправка формы недоступна.

Тема генерируется из tokens.css; `theme.generated.css` не редактируется вручную. Manrope и Golos Text загружаются локально. Общие компоненты требуют регрессии всех шаблонов.

## Заявки

`contact-form.astro` → `forms.ts` → same-origin `POST /api/leads` → серверная валидация → transport interface → подтверждение получателя. Успех возможен только после ack. Ошибка сохраняет ввод на странице; browser storage формы не используется.

До согласования поля disabled, API отвечает 503 без чтения тела. `server/index.mjs` слушает только loopback, не отдаёт файлы и не выбирает получателя. Будущий reverse proxy направляет `/api/leads` в отдельный сервис. Реализация не требует перевода сайта на SSR. Контракт, env и ограничения — [forms-integration](forms-integration.md).

## Privacy, аналитика и SEO

Выбор аналитики отделён от согласия формы. Метрика требует code-reviewed legal gate, production-mode, ID, feature flag, совпадения origin и пользовательского opt-in. Цели ограничены списком; значения полей не передаются. При отзыве сбор останавливается и доступные first-party идентификаторы очищаются в документированных пределах. [Analytics](analytics.md), [privacy implementation](privacy-implementation.md).

SEO-head формирует metadata/canonical/OG и подтверждённую structured data. robots/sitemap строятся из конфигурации; staging закрыт, sitemap пуст. Одним env нельзя разрешить индексирование юридических черновиков. Redirect registry проверяется на полноту/цепочки; production требует host-specific применения. [SEO migration](seo-migration.md).

Hosting, delivery credentials, юридическое согласование и DNS остаются решениями владельца. In-memory limiter/idempotency рассчитаны на один процесс; масштабирование требует общего согласованного store. Типизированные данные обеспечивают обновление разработчиком, но не являются административной панелью.

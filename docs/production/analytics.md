# Яндекс Метрика

Статус: подготовлена, **выключена до публикации**. Счётчик владельца — 114386722 (передан 2026-11-20), записан в `.env.example` как `PUBLIC_METRICA_ID`; в production его значение задаётся в окружении хостинга. Включается только по условиям ниже, до согласия посетителя ничего не загружается. Тесты заменяют SDK изолированной заглушкой и не отправляют запросов.

Стандартный код Метрики (вставка `<script>` в `<head>` и `<noscript>`-пиксель) на сайт **не вставлен**: он грузился бы до выбора посетителя. Вместо него — `src/scripts/analytics.ts`: тот же `tag.js`, но только после согласия. Из параметров кода владельца включены `webvisor` и `clickmap` (решение 2026-11-20), `trackLinks` и `ecommerce` — нет (см. «Настройки и отзыв»).

## Условия работы

Все условия должны выполняться одновременно:

- утверждённые тексты и `legal_content_approved = true` в `src/data/site-config.ts`;
- `PUBLIC_SITE_MODE=production`;
- `PUBLIC_LEGAL_APPROVED=true`;
- `PUBLIC_ANALYTICS_ENABLED=true`;
- корректный положительный `PUBLIC_METRICA_ID`;
- origin страницы совпадает с `PUBLIC_SITE_URL`;
- неистёкший выбор analytics=true в consent.

Переменные PUBLIC открыты в клиентском коде; помещать в них секреты нельзя. Staging всегда выключает счётчик, даже если туда ошибочно скопировали ID. Загрузка SDK только после согласия, повторная проверка выполняется после его загрузки. Нет pixel/noscript обхода согласия.

## Цели

В кабинете создаются JavaScript-события с именами:

| Имя | Событие |
|---|---|
| callback_click | Заказать звонок |
| services_click | Переход к услугам |
| projects_click | Каталог проектов |
| phone_click | Телефонная ссылка |
| email_click | Почтовая ссылка |
| form_open | Открытие обращения |
| form_start | Первое взаимодействие с включённой формой |
| lead_success | Только подтверждённый успешный ответ обработчика после доставки |
| project_open | Переход к конкретному проекту |
| vacancy_response | Зарезервировано до разрешённого запуска откликов |

Цель получает только фиксированное имя из allowlist. Имя, телефон, e-mail, сообщение, контекст формы и произвольные параметры не передаются. Автосбор исходящих ссылок выключен. Просмотр передаёт canonical без query/hash, с пустым referer/title. Данные не включаются в URL формы.

## Настройки и отзыв

`defer=true` отключает автоматический первоначальный просмотр; затем отправляется очищенный `hit`. `webvisor` и `clickmap` — true (решение владельца 2026-11-20, только после согласия посетителя); `trackLinks`, `accurateTrackBounce`, `trackHash`, `ecommerce`, `sendTitle` — false; `disableYtm=true`. Форма обращения помечена классом `ym-disable-keys`, нажатия клавиш в ней Вебвизор не записывает. Вебвизор пишет адрес страницы как есть (с query/hash, если они есть): очищенный `hit` на него не влияет. Перед включением счётчика юристу нужно утвердить текст уведомления о Вебвизоре (`/cookies`, окно настроек куки).

При отзыве: запрет целей немедленно, `ym(id, 'destruct')`, очистка очереди и доступных first-party идентификаторов. Отменённая загрузка не инициирует счётчик после повторного согласия. Удаление уже доставленных данных у поставщика отдельным процессом; обещания их удалить в интерфейсе нет.

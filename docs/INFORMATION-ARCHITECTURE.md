# INFORMATION-ARCHITECTURE — информационная архитектура нового сайта СЭС

Фаза PHASE 1C, скорректирована патчем demo-first (2026-10-13: A-17…A-23). Дата: 2026-10-13. Статус документа: **Proposed — полная архитектура ожидает согласования заказчиком**. Ни одна страница, меню или шаблон здесь не имеют статуса Approved. Утверждёнными остаются только решения из [DECISIONS.md](../DECISIONS.md) (раздел Approved).

Что это: структура, навигация, состав страниц и связи. Чего здесь нет: дизайна, CSS, форм на уровне полей и серверной части, выбора стека, новых текстов. Тексты сайта переносятся дословно из [docs/content/source/](content/source/); новыми являются только интерфейсные подписи (A-03), они помечены **(подпись — Proposed)**.

Связанные документы: [URL-MIGRATION.md](URL-MIGRATION.md) (судьба всех 50 старых URL), [UX-AUDIT.md](UX-AUDIT.md) (замечания `U-xx`, рекомендации `UX-R-xx`), [CONTENT-MAP.md](CONTENT-MAP.md), [URL-INVENTORY.md](URL-INVENTORY.md), [SITE-AUDIT.md](SITE-AUDIT.md), [ASSET-REQUIREMENTS.md](ASSET-REQUIREMENTS.md).

Метки статуса связи услуга ↔ проект (§7): **SOURCE_SUPPORTED** — основание есть в тексте источника; **PROPOSED** — по смыслу, но признак в тексте не назван; **PENDING** — оснований нет. Отдельный уровень **CLIENT_APPROVED** — соответствие подтверждено заказчиком (пока ни одно). Метка **DESCRIPTION_PENDING** — описание услуги ожидает заказчика. Метка **REVIEW** — решение по содержанию не принято, содержание сохранено. Условная страница или блок — показывается только при выполнении условия из §3.4.

Идентификаторы: `PG-xx` — страницы, `H-xx` — секции главной, `T-xx` — шаблоны, `S-xx` — услуги, `PRJ-xx` — проекты (`PRJ-14-xx` — виды работ ТЛТ), `D-xx` — решения (§9), `R-x` — риски (§10), `Q-xx` — вопросы заказчику. Идентификаторы `A-xx`, `P-xx`, `Q-01…Q-16` относятся к [DECISIONS.md](../DECISIONS.md).

Принципы структуры:

1. **Каждое изменение отвечает на конкретную проблему аудита** (см. §9, колонка «Проблема»).
2. **Страница создаётся, только если есть содержание для неё.** Нет описаний услуг — нет страниц услуг. Нет документов — нет публичной страницы документов.
3. **Пустое не показывается.** Блоки и пункты меню без содержимого скрыты (§3.4).
4. **Текст не меняется.** Переносятся, объединяются, переставляются блоки. Правки и исправления опечаток только по согласованию (Q-24).
5. **Расширяемость данными, а не вёрсткой.** Новая услуга, проект, вакансия, новость или документ добавляются как запись, структура не перестраивается.

Страницы из названия и ссылок на проекты были бы тонкими и потребовали выдуманных текстов. Это **альтернатива для развития:** `/services/{slug}` появляется, когда заказчик предоставит описание услуги; URL-схема зарезервирована, текущие якоря `/services#{slug}` потом получают 301 на отдельную страницу.
- **Риск решения:** запросы вида «ГНБ Благовещенск» не получают целевой страницы услуги (в метаданных старого `/services` ГНБ указан). Принят осознанно ради отказа от выдуманного контента.

## 7. Связи между страницами

### 7.1 Правила

| Связь | Реализация | Условие |
|---|---|---|
| Услуга → проекты | В карточке услуги блок «Проекты по направлению» | есть связь с `CLIENT_APPROVED` (в демо — `SOURCE_SUPPORTED` с пометкой, §12.3) |
| Проект → услуги | Теги услуг на карточке и странице проекта | то же |
| Проект → другие проекты | «Предыдущий / следующий» всегда; «Другие проекты» по общей одобренной услуге | иначе блока нет |
| ТЛТ ↔ виды работ | Карточки «Виды работ» ↔ «К объекту ТЛТ» | всегда |
| Главная → разделы | Кнопки hero, H-02, H-03, H-04 | всегда |
| Любая содержательная страница → Контакты / Заявка | Шапка, нижняя панель на mobile, CTA-баннер, подвал | всегда |
| Заявка → Политика | Ссылка в согласии | всегда |

Пустые блоки «Похожие проекты» не выводятся. Соответствия не выводятся из тематики догадкой: в продакшене связь появляется в интерфейсе только после `CLIENT_APPROVED` (Q-17). Совпадение терминов в тексте (`SOURCE_SUPPORTED`) — основание для вопроса заказчику, а не его ответ. **Исключение для демо (Proposed, §12.3):** связи `SOURCE_SUPPORTED` могут показываться с явной пометкой «предварительно, на согласовании»; PROPOSED и PENDING не показываются никогда.

### 7.3 Два уровня проверки связи (A-20)

**Уровень 1 — основание в источнике** (что сказано в тексте старого сайта):

- **SOURCE_SUPPORTED** — в тексте самого проекта есть тот же признак, что в названии услуги: метод «ГНБ», слово «видеонаблюдение», либо тот же вид работ и класс напряжения.
- **PROPOSED** — работы по смыслу относятся к услуге, но признак из названия услуги в тексте не назван (другой вид работ, напряжение не указано, способ прокладки не указан). Это гипотеза.
- **PENDING** — оснований нет. Для PENDING-связей указаны кандидаты и причина отказа; в интерфейсе они не используются.

**Уровень 2 — согласование заказчиком:**

- **CLIENT_APPROVED** — заказчик подтвердил, что проект соответствует услуге. Значение «да» ставится только на основании ответа заказчика (Q-17), не по совпадению терминов. **Сейчас «да» нет ни у одной из 40 строк.**

Уровень 1 не заменяет уровень 2: даже `SOURCE_SUPPORTED` — это «основание есть в тексте», а не «утверждено». К согласованию заказчику предлагаются в первую очередь `SOURCE_SUPPORTED`; PROPOSED — после подтверждения.

### 8.3 Форма заявки (без технического проектирования)

- **Назначение.** F-1 — обращение заказчика (услуга, проект, общий вопрос). F-2 — отклик на вакансию, канал не утверждён (Q-13). Один компонент, разный контекст.
- **Где вызывается.** Диалог из шапки и нижней панели; встроенная на `/contacts` и в H-05; из карточки услуги, страницы проекта, вакансии. Без JS — переход на `/contacts#request`.
- **Данные, которые могут потребоваться** (поля, обязательность и порядок утверждаются позже): имя, телефон, услуга / проект / вакансия (из контекста), сообщение, e-mail (необязательный; в старой форме он шёл первым — U-18), согласие на обработку ПДн.
- **Обязательные юридические элементы** (проверить юристом): отдельный флажок согласия без предустановки, отделённый от других подтверждений; ссылка на актуальную `/privacy`; указание оператора (ООО «Связь Энергострой»; ИНН, ОГРН, адрес — PENDING); цель обработки; способ отзыва согласия; хранение и локализация данных (P-03); отсутствие персональных данных в URL; согласие на cookie — при подключении Метрики (A-09, Q-14). Требования 152-ФЗ в части согласия менялись в 2025 г.; формулировки и форма согласия — на проверку юриста.
- **Подписи формы** (заголовок «Мы рады сотрудничать с Вами!», подпись «Заполните данные и мы свяжемся с Вами в ближайшее время», сообщения об успехе) переносятся из источника; два варианта успеха («Благодарим за обращение в ООО "Связь Энергострой"» и «Ваш заказ принят!») — выбор Q-23.
- **Не решается здесь:** канал доставки, серверная часть, антиспам (Q-05).

### 12.3 Правила демо (A-23)

**Формы.** Демонстрационный интерфейс заявки: поля, проверка, состояния. Форма **не отправляет данные** (нет сетевого запроса), **не сохраняет ввод** (нет серверного хранения, `localStorage`, cookie), **не создаёт впечатления доставки**: итоговое сообщение явно говорит, что это демонстрация и заявка не отправлена (подпись — Proposed). Сообщения об успехе из источника («Благодарим за обращение…», «Ваш заказ принят!») в демо не используются. Канал доставки не выбран (Q-05) и не имитируется.

**Честная пометка незавершённого.** Пункты и ссылки на страницы POST-DEMO, неактивные карточки, заглушки фото, `ADDRESS_PENDING`, форма — помечены видимо и понятно. Нет «мёртвых» ссылок без пояснения. Заглушки фото — явные (A-06); сток не выдаётся за проекты СЭС. На демо виден признак «Демо-версия» (подпись — Proposed).

**Тексты.** Только существующие тексты сайта дословно; новые — только интерфейсные подписи (Proposed). Цифры, даты, заказчики и проекты не придумываются. У «Проектирования» — только название.

**Закрытый предпросмотр.** Если заказчик смотрит демо по ссылке: доступ защищён (пароль или эквивалент), страницы не индексируются (`noindex`, закрытый `robots.txt`), аналитики и сторонних сервисов нет. Выбор механизма и хостинга — PHASE 2; учётные данные не хранятся в репозитории. Способ показа — Q-28.

**Production.** Действующий `ses-dv.ru` не изменяется: ни DNS, ни редиректов, ни файлов, ни настроек. Демо живёт на отдельном адресе. Редиректы из [URL-MIGRATION.md](URL-MIGRATION.md) в демо не реализуются.

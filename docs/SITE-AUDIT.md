# SITE-AUDIT — фактические наблюдения при обходе https://ses-dv.ru/

Фаза PHASE 1A. Дата обхода: 2026-10-12. Только факты, без рекомендаций по новой структуре. Источник каждого наблюдения — URL, указанный рядом, либо `docs/URL-INVENTORY.md` / `docs/content/source/`.

## 1. Метод и охват

- Окружение: локальный Windows, `curl.exe` и Python (стандартная библиотека), затем проверка отрисовки во встроенном браузере. User-Agent: полный браузерный (часть проверочных запросов с коротким «Mozilla/5.0» получила 403 от ddos-guard; те же запросы с полным UA прошли; причина — UA или частота запросов — не установлена).
- Получены сырые HTML 50 страниц (41 из sitemap + 9 дополнительных), `robots.txt`, `sitemap.xml`; HTML держался вне репозитория (рабочий каталог, не коммитится).
- Извлечение: разбор DOM Tilda → тексты, заголовки, кнопки, ссылки, изображения, формы, SEO-метаданные. Проверка полноты: каждый текстовый узел основной части HTML сопоставлен с извлечённым текстом — пропущено 0.
- Отрисованный вид сверен в браузере: `/` (весь текст основной части совпал с извлечённым), `/news` («Feed not found.»), `/worker` (попап вакансии открылся и содержит извлечённый текст).
- Формы не отправлялись; единственные «интерактивные» действия — открытие попапа вакансии на `/worker` (клик «Подробнее») и чтение DOM.
- Размер HTML страниц: от 9 до 268 КБ.

## 4. Редиректы и варианты URL

- `http://` → `https://` через 301.
- `https://www.ses-dv.ru/…` отдаёт 200 **без редиректа** (дубль хоста; canonical указывает на `ses-dv.ru`).
- `/services/` (со слэшем) и `/Services`, `/SERVICES` отдают 200 с тем же содержимым (canonical — строчный адрес без слэша).
- Несуществующий адрес (`/old-page-xyz`) → 404; `/index.html` → 404. `/error` и `/page36950621.html` отдают шаблон 404 с кодом **200** (мягкая 404).
- Редиректов 3xx между страницами сайта не обнаружено.

## 7. Динамический контент и неработающие функции

- **Лента новостей не работает**: на `/news`, на `/` (блок «НОВОСТИ») и на `/about` отображается «Feed not found.». Кнопки «ПОДРОБНЕЕ» / «ВСЕ НОВОСТИ» остаются в разметке. Пункт «Новости» присутствует в меню и подвале.
- Вакансии: «Подробнее» на `/worker` и `/engineers` открывает попап-описание (URL вида `#!/tproduct/…`). Работает (проверено на `/worker`). Описание вакансий в HTML есть, но скрыто в попапах.
- На `/services` 9 кнопок «Заказать» открывают форму заказа; на `/` «Подробнее» открывает попапы со сканами СРО.
- Формы: в каждой форме есть скрытое поле `formservices[]` (признак встроенного обработчика Tilda; в шапке и на `/services`, `/advantages`); получатели заявок не проверялись, отправка не выполнялась.
- Якорные ссылки (`#popup:*`, `#zeropopup*`, `#submenu:more`, `#menuopen`) указывают на существующие элементы страниц; `#prodpopup` обрабатывается скриптом Tilda (проверено кликом на `/worker`).

## 14. Ограничения исследования

- Не проверялось фактическое состояние индекса Яндекс/Google, позиции, трафик, поведенческие данные (нет доступа к Вебмастеру/Search Console/Метрике).
- Изображения не скачивались и визуально не просматривались (скриншоты браузерной панели при проверке были недоступны); содержимое сканов и логотипов неизвестно. OCR не выполнялся.
- Порядок строк в Zero-блоках Tilda восстановлен по desktop-координатам; это приближение (в `home.md`, `services.md` и др. отмечено).
- Дата сайта «© 2024», sitemap lastmod 2025-10-30: актуальность текстов (вакансии, проекты, контакты) не проверялась.
- Лента новостей недоступна: невозможно установить, были ли опубликованные новости в Tilda ранее.
- Проверялись GET-запросы без авторизации; админ-часть Tilda и неопубликованные страницы недоступны. Список страниц ограничен sitemap, навигацией, robots.txt и внутренними ссылками; страницы без ссылок и без записи в sitemap/robots обнаружить нельзя.
- Соответствие «Оснащение = /mtb» выведено из подписи пункта меню; подтверждение заказчика не получено.
- Часть запросов с коротким User-Agent получила 403 от ddos-guard; в выводах использованы только результаты с полным браузерным UA. Возможны сетевые ограничения по частоте запросов, поэтому обход велся с паузой 0,4 с между запросами.
- Обход состоял из GET-запросов страниц и ресурсов; данные сайта не изменялись, формы не отправлялись. Загрузки страниц (в том числе во встроенном браузере, где исполняются скрипты) могли быть учтены счётчиком Яндекс.Метрика и статистикой Tilda как визиты.
- Палитра, UX-аудит и анализ вёрстки в эту фазу не входили (PHASE 1B).

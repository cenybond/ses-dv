# Правила визуальной системы полной версии

Основной документ — `DESIGN-SYSTEM.md`; токены — `design/system/tokens.css`. Эта инструкция описывает применение системы в полной версии, не создаёт вторую систему.

## Идентичность

- Брендовый зелёный — `--color-brand`; салатовый — `--color-accent`, для кнопок и акцента Hero. Салатовый текст на светлом фоне не использовать.
- Локальные Manrope и Golos Text, оригинальные SVG из `design/system/logo/`. Новые шрифты и перерисованный логотип не добавлять.
- Радиусы зависят от роли: pill для основного CTA и компактной навигации; `--radius-lg` для изображения/карточки; `--radius-xl` для большого контактного блока. Не превращать контентные контейнеры в pill.
- Поверхности преимущественно светлые. Тёмные зоны — Hero и заключительное обращение/подвал. Зелёные заливки не служат фоном каждой секции.

## Композиционный ориентир

Просмотрен исходный `evermod-home-desktop.webp` из основного репозитория и desktop/mobile Hero V4. Из EverMod используются композиционные принципы: выразительный первый экран, крупный типографический акцент, спокойная светлая основа, понятный ритм и ведущая роль реальной фотографии. Фотографии, тексты, логотип, показатели и уникальные материалы EverMod не переносятся.

Hero полной версии сохраняет V4. На desktop заголовок расположен слева поверх нейтрального затемнения; справа читается изображение. На mobile текст и полный кадр образуют последовательные блоки. Подпись честно называет кадр временной иллюстрацией, не объектом компании. Отсутствие клиентских фотографий нельзя компенсировать вымышленными объектами.

## Разные задачи — разные шаблоны

| Шаблон | Композиция | Правило |
|---|---|---|
| Главная | Hero, направления, корпоративные секции, проекты, контакты | Один ведущий CTA; не повторять Hero на внутренних страницах |
| Услуги | Короткое введение, переходы к якорям, двухколоночный каталог | Полные исходные названия; одинаковая роль карточек объясняет их общий размер |
| Каталог проектов | Трёхколоночная сетка изображений и названий | На tablet 2 колонки, на mobile 1; название не обрезать |
| Проект | Полный заголовок, боковая навигация, текст и галерея | Не дополнять пустоты неподтверждёнными характеристиками |
| ТЛТ | Заголовок объекта, подтверждённые сведения, галерея, перечень работ | 12 работ доступны по отдельным ссылкам |
| Вид работ | Компактный заголовок, исходное описание, галерея | Длинный текст полностью читается; текущая крошка обозначает роль страницы |
| О компании | Редакционная асимметричная сетка, тезис, преимущества, подразделения | Избегать превращения всех абзацев в одинаковые карточки |
| Вакансии | Две группы и нативные раскрывающиеся описания | Статус набора выражен словами, без фиктивного активного найма |
| Контакты | Контакты слева, форма справа; на mobile последовательно | Телефон и почта доступны даже при отключённой отправке |

## Типографика и длина содержания

Основные стили — `--type-h1`, `--type-h2`, `--type-h3`, `--type-body` и связанные токены. Обычный внутренний H1 использует шкалу внутренних страниц. Названия проектов получают компактную разновидность. Для исходных заголовков длиннее 180 символов используется `--type-h2-sm` на desktop и `--type-lead` на mobile с интерлиньяжем 1.3. Этот порог меняет оформление, не текст.

В breadcrumbs длинных детальных страниц достаточно «Проект» или «Работы на объекте»: полное название остаётся в единственном H1. Нельзя скрывать часть исходного H1 многоточием или исправлять повторяющиеся слова без редакционного согласования.

Карточки не имеют фиксированной высоты текста, строки переносятся. В сетках используются `minmax(0,1fr)` и `min-width:0`. Контентные абзацы ограничены шириной; на mobile таблицы и колонки не должны создавать горизонтальную прокрутку.

## Изображения и галереи

`ProjectCard` и `project-gallery.astro` имеют честные состояния отсутствия фотографии. Они не являются доказательством выполненных работ. Перед финальным показом кейсов необходимы утверждённые снимки каждого объекта.

При добавлении изображения обязательны осмысленный `alt`, размеры `width`/`height`, оптимизированный файл и проверка кадрирования. В галерее оригинальный кадр показывается без принудительного `cover`; обложка каталога может использовать `cover` после ручного просмотра desktop/mobile. Фотографии ниже первого экрана загружаются лениво.

## Интерактивные элементы

- Переходы — ссылки; управление диалогами — кнопки; раскрывающиеся вакансии — `details/summary`.
- Видимый фокус, skip-link, сохранение клавиатурного доступа и возврат фокуса после диалога обязательны.
- Для touch используется проектная цель `--size-touch`. Нижняя панель учитывает safe area; документ оставляет запас под ней.
- Отключённая форма прямо сообщает причину и оставляет альтернативные контакты. Ввод не должен выглядеть доступным, когда обработка не включена.
- Движение функциональное и короткое; учитывать reduced motion. Декоративные autoplay/параллакс не нужны.

## Проверка после изменений

Минимум: `npm run check-tokens`, сборка, ссылки и браузерный прогон на 320/390/768/1024/1440. Проверять desktop/mobile каждого изменённого шаблона, длинное название ТЛТ, открытую вакансию, форму и шторку меню. Измерение токенов не заменяет проверку текста поверх фотографии. Скринридер, другие браузеры и реальные устройства отмечать отдельно, если не проверялись.

Дополнительный источник правил: [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md), прочитан 2026-10-27. При конфликте общих советов с дословными источниками, пользовательским заданием и системой СЭС приоритет имеют требования проекта.

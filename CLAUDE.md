## Жёсткие ограничения
- Тексты старого сайта переносим дословно. Любая правка текста только после согласования.
- Из старого дизайна сохраняем только корпоративную палитру (HEX с источником).
- Разделы «Благодарности» и «Оснащение» исключены. Остальное не удалять без согласования.
- Адрес: `ADDRESS_PENDING`. Старый адрес в финальный сайт не переносить.
- Фото: только явные заглушки до получения фото от заказчика. Не выдавать сток за проекты СЭС.
- Не подключать аналитику, сторонние сервисы доставки заявок, CMS и backend без отдельного решения.
- Удалённые URL не редиректить на главную автоматически.
- Демо: формы не отправляют и не хранят данные; недействующее не выдавать за рабочее.
- Дизайн: только токены `--color-*`, `--type-*`, `--space-*`, `--radius-*` из `tokens.css`, без HEX и новых размеров в компонентах; салатовый `--color-accent` на светлом не несёт текст. Новые цвета, шрифты, декор — только через `DECISIONS.md`.
- Сетка (решение владельца 2026-11-18): все разделы сайта стоят на сетке hero главной. Левая ось — левый край заголовка hero (поле карточки `--space-6` + отступ текста `--space-12` = 72 px на десктопе; ≤960 px — `--gutter` + `--space-6`; ≤360 px — `--gutter` + `--space-3`), правая — симметричная. Контейнер 1200 px для секций не используется: ширина контента = 100% − 2 осей. На главной это `--axis` в `src/styles/home.css` (`.home-rest .container`); новые и переделываемые страницы подключают ту же ось, не вводят свои поля. Шапка и карточка hero — поле 24 px от края.
- Шрифт-эталон (решение владельца 2026-11-18): раздел «О нас» на главной (Figma Frame 4, узел 37:472) — образец типографики для всех разделов сайта. Заголовок раздела — `--type-about-title` + `--ls-about-title` (Inter SemiBold 44, −5 %); лид, подписи под заголовком и крупный текст — `--type-about-lead` + `--ls-about-lead` (Inter Regular 24, −2 %), цвет `--color-text`; пункты списков — `--type-about-item` + `--ls-about-item` (Manrope SemiBold 22, −3 %). Новые разделы берут эти токены, а не `--type-h2`/`--type-lead`/`--type-body-lg`; переделываемые разделы приводятся к ним. Вес и семейство не менять, новые размеры — только через `DECISIONS.md`.
- Логотип: единственный источник — `brand/source/logotip-vektor.pdf` (не изменять); не перерисовывать, не растягивать, не менять шрифт, не перекрашивать (кроме белого названия на тёмном); SVG пересобираются `python -I brand/build_logo_svg.py`.

## Архитектурные правила Astro (PHASE 5.1)
- Стили: `src/styles/global.css` импортирует `design/system/*` в слои `theme` → `components` → `utilities`. Не копировать CSS, шрифты и SVG в `src/`; `theme.generated.css` не править вручную.
- В `src/` нет HEX, `rgb()` и произвольных размеров вида `[12px]` (проверяет `check-tokens`); цвета, радиусы, тени — токенами/утилитами `bg-brand`, `rounded-lg`. Компоненты системы (`.btn`, `.service`…) не усложнять утилитами `display`/размеров (P-27).
- Ссылки в интерфейсе только на существующие страницы; готовность маршрутов — `src/data/nav.ts` (`built`). `check-dist` печатает ожидающие страницы.
- Данные (DEMO-03): тексты живут только в `src/data/` — `source/*` (S, дословно, каждая строка `{text, src}` со ссылкой на снимок `docs/content/source/`), `ui.ts` (U, подписи интерфейса), `index.ts` (выборки). Новый текст — только с `src`; опечатки источника не править; `*_PENDING`, `SOURCE_SUPPORTED`, `CLIENT_APPROVED` — внутренние маркеры, в интерфейс не выводить. После правки данных — `npm run check-copy`.
- Навигация (DEMO-04): пути только из `src/data/nav.ts` (`routes`, `mainNav`), `aria-current` — через `NavigationLink`; недоступное не выводить ссылкой (компонент `InertNote` удалён при чистке 2026-11-19 как неиспользуемый); новый маршрут = страница + `built: true` + проходит `check-links`. Поведение — `src/scripts/` (шапка, шторка меню); `design/system/system.js` в Astro не подключается (P-30).
- Логотипы — `src/components/Logo.astro` (SVG из `design/system/logo/`, не менять; `check-dist` сверяет байты).

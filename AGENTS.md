# СЭС — инструкции для Codex

Корпоративный сайт ООО «Связь Энергострой»: Astro 7, TypeScript 6, Tailwind 4, статическая сборка. Работай в существующем репозитории, ветка `integration/docs-and-skills`; не переключай её без необходимости.

## Контекст и ограничения

- Сначала прочитай [CLAUDE.md](CLAUDE.md) и текущий статус в [PROGRESS.md](PROGRESS.md). `CLAUDE.md` остаётся действующим документом проекта. Затем читай только разделы документов и файлы текущей задачи; решения — в [DECISIONS.md](DECISIONS.md), правила визуальной системы — в [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md).
- Глобальные пользовательские инструкции сохраняются. Новые обычные имена файлов и переменных — на английском, маленькими буквами; обязательные имена `AGENTS.md` и `SKILL.md` сохраняй. Не переименовывай существующие файлы ради этого правила.
- Production `ses-dv.ru`, сервер, CMS, backend, аналитика и внешняя доставка заявок вне задачи. Демо не отправляет и не хранит персональные данные. Не повторяй аудит действующего сайта.
- Тексты источника переноси дословно, включая опечатки: снимки `docs/content/source/` неизменяемы; данные S с `{text, src}` — в `src/data/source/`, подписи U — в `src/data/ui.ts`. Не выдумывай контакты, адрес, проекты, цены, сроки и показатели. Внутренние маркеры не выводи в интерфейс.
- Единственный источник токенов — `design/system/tokens.css`. Используй существующие `--color-*`, `--type-*`, `--space-*`, `--radius-*` и компоненты; новые значения требуют решения проекта. `src/styles/theme.generated.css` генерируется, вручную его не правь. CSS, WOFF2 и SVG из `design/system/` не дублируй в `src/`.
- Логотип: неизменяемый оригинал `brand/source/logotip-vektor.pdf`, готовые SVG — `design/system/logo/`, Astro-компонент — `src/components/Logo.astro`. Не меняй геометрию, шрифт и пропорции, не дублируй название рядом с логотипом. Горизонтальная перекомпоновка отдельно не утверждена.

## Презентация Hero и следующий этап

`design/client-preview/hero/index.html` и `styles.css` — отдельная презентация; фон `assets/hero-bg-house.webp` — временная иллюстрация, не объект СЭС. Исходный референс — `design/references/evermod/evermod-home-desktop.webp`, прототип — `design/explorations/ses-home-v1/`. `/` в Astro — служебная проверка каркаса, не эта презентация.

C0 ограничен подготовкой Codex: не менять `src/`, Hero, фон, логотип, дизайн-систему и тексты продукта. Следующая отдельная задача — **HERO VISUAL REFINEMENT V4**, требования зафиксированы в [docs/codex-handoff.md](docs/codex-handoff.md). Не начинать её и DEMO-05 автоматически. Сохранение текущей иллюстрации и CTA «Наши услуги» / «Проекты» относятся к поручению V4, а не к разрешению менять фото и тексты всего сайта.

## Проектные скиллы

- Codex обнаруживает входные файлы `.agents/skills/<name>/SKILL.md`. Они ссылаются на оригиналы `.claude/skills/`; ресурсы и относительные ссылки оригинала разрешай от его каталога. Исходные скиллы не переустанавливай.
- Для визуальной задачи выбирай только нужное: `build-design` → `better-layout` → `better-typography` → `web-design-guidelines` → `better-accessibility`. Это порядок приоритета, а не требование загрузить все пять.
- `ui-ux-pro-max` — дополнительная адресная проверка; не генерируй альтернативную дизайн-систему для существующего проекта. `animate` — только при конкретной задаче на анимацию, для V4 не нужен.
- Требования пользователя, утверждённый контекст СЭС и входной файл Codex имеют приоритет над общими рецептами оригинального скилла. EverMod задаёт композиционные принципы, не бренд и не тексты. Не меняй дословные тексты ради типографики; рекомендации по размерам не заменяют токены. Не устанавливай отсутствующие родственные скиллы и библиотеки автоматически.
- Проверить обнаружение можно через `codex app-server`, метод `skills/list` с `cwds` корня репозитория и `forceReload: true`; порядок ручной проверки — в handoff. Эта беседа запущена вне репозитория, поэтому её каталог скиллов не подтверждает каталог проектной беседы.

## Проверки и завершение

- Команды и фактический состав проверок — `package.json`: `npm run check`, `build`, `check-tokens`, `check-copy`, `check-dist`, `check-links`, `check-browser`; полный набор — `npm run verify`. Проверки `dist` и браузера запускаются после сборки. После данных — `check-copy`; после токенов — `sync-theme` и `check-tokens`. Для одних документов/подключения скиллов достаточно адресных проверок, полный `verify` не обязателен.
- Браузер: существующий Edge/Chrome через `scripts/check-browser.mjs`; ширины 320 / 390 / 768 / 1024 / 1440. Не устанавливай пакеты, браузеры и глобальные зависимости без объяснения. При отсутствии `node_modules` сообщи и предложи восстановление `npm ci` по lockfile, не запускай его молча.
- Перед изменениями проверь ветку, коммит, `git status` и чужие изменения. Перед коммитом — `git status`, `git diff`, `git diff --check`, просмотр staged diff; включай только файлы своей задачи, без секретов. Один завершённый шаг — один атомарный коммит; фиксация и push только в рамках поручения, без force push, без изменений `main` и без PR для C0.
- Обновляй `PROGRESS.md`, кратко сообщай результат, проверки, изменённые файлы и непроверенные пункты. После текущего задания остановись.
